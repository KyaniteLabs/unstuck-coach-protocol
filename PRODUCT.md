# Unstuck Coach protocol

A portable, folder-based executive-function accessibility coach for moments when starting, switching, remembering, regulating, capturing or closing a life loop becomes difficult. Its core experience is **State → Friction → Move → Hold → Check → Close**: protect dignity, hold the rest of the pile, offer one humane next move and ask for tiny proof—not a productivity lecture or a long menu.

## What exists

- [PROJECT_INSTRUCTIONS.md](PROJECT_INSTRUCTIONS.md), identity/rules/examples and [reference](reference/) files form the host-model coaching contract. Load them into a supported AI workspace; this repository does not supply that model runtime.
- Stance routing covers ally/stabilize, choose, execute, remember and recover/close, with calendar/inbox playbooks, capture/re-entry, body-state and safety boundaries. Supplied context should reduce repeated self-reporting; external writes still require approval.
- First-run and first-reply scorecards, demo transcript/before-after packs, red-face scenarios and research-to-behavior checklists provide inspection/evaluation material. These are curated artifacts and requirements, not a clinical dataset or proof every host model follows them.
- [landing](landing/) contains a static review/demo deck, a keyword-based interactive coach console, an evidence reader and a pitch-reel page. The console is deterministic sample routing, **not live LLM coaching**.
- Node scripts check copy, routing, bundle/publication boundaries and other contracts, and can build evidence/publication artifacts.

## Repository boundary

As [docs/repository-separation.md](docs/repository-separation.md) states, this is the protocol/publication artifact—not [unstuck-coach-live](https://github.com/KyaniteLabs/unstuck-coach-live) and not [Innerscape](https://github.com/KyaniteLabs/Innerscape). Offline integration planning does not establish a completed merge, OAuth/calendar sync or an approved combined hosted service.

## Limits

The coach is not diagnosis, treatment, medication advice or crisis care. Host-model compliance and actual benefit require separate evaluation. The browser console and coaching prose can differ: for example, the bundled “whole-life freeze” console case selects externalizing loops while the project instructions prescribe a body-first move. A passing console test confirms the implementation's expected routing, not clinical or protocol correctness. No real account access, messages or calendar edits are provided by this static console.
